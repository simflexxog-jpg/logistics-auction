# Deployment Guide

## Render Deployment

### Issue: PostgreSQL Connection Failure
If you see errors like:
```
DB sync failed: HostNotFoundError [SequelizeHostNotFoundError]: getaddrinfo ENOTFOUND dpg-d9freov7f7vs73bpiur0-a
```

This means the PostgreSQL database is not available or misconfigured.

### Solution Options

#### Option 1: Use SQLite (Recommended for Testing/Free Tier)
1. In your Render dashboard, go to your service's **Environment** settings
2. Add or uncomment this environment variable:
   ```
   FORCE_SQLITE=true
   ```
3. Redeploy
4. The app will now use SQLite database file (`logistics.db`) instead of PostgreSQL

#### Option 2: Fix PostgreSQL Database
1. In your Render dashboard, verify that the PostgreSQL database service is:
   - Created and running
   - Connected to your web service
   - Properly configured with the correct name and credentials

2. The database should be created from the `render.yaml` file:
   ```yaml
   databases:
     - name: logistics-auction-db
       plan: free
       databaseName: logistics_auction
       user: logi_user
   ```

3. If the database doesn't exist, delete the service and redeploy to trigger database creation

### Environment Variables

The following environment variables are used:

| Variable | Purpose | Example |
|----------|---------|---------|
| `NODE_ENV` | Environment mode | `production` |
| `PORT` | Server port | `3000` |
| `DATABASE_URL` | PostgreSQL connection string | Auto-generated by Render |
| `JWT_SECRET` | JWT signing secret | Auto-generated |
| `FRONTEND_URL` | Frontend URL for CORS | `https://logistics-auction.onrender.com` |
| `FORCE_SQLITE` | Force SQLite instead of PostgreSQL | `true` (optional) |

### Production Build

The production build is automatically created by the `buildCommand` in `render.yaml`:
```bash
npm install --legacy-peer-deps --include=dev && npm run build
```

To test locally:
```bash
npm run build
NODE_ENV=production npm run start:server
```

Then visit: `http://localhost:3000`

### Database Fallback Logic

The app now includes intelligent database selection:

1. **If `FORCE_SQLITE=true`**: Uses SQLite immediately
2. **If `DATABASE_URL` is set**: Attempts PostgreSQL connection
3. **Otherwise**: Uses SQLite

The server will continue running even if database sync fails, allowing the frontend to be served. API endpoints will work once the database becomes available.

### Local Development

For local development, the `.env` file configures:
```
NODE_ENV=development
PORT=3000
# DATABASE_URL is commented out to use SQLite
```

To use PostgreSQL locally:
1. Uncomment `DATABASE_URL` in `.env`
2. Update it to point to your local PostgreSQL instance
3. Restart the server

### Troubleshooting

**App exits after "DB sync failed"**
- This was the previous behavior. Now the app continues running and serves the frontend.
- API endpoints will fail with "database not available" errors until the database is ready.

**"Cannot find module 'sqlite3'"**
- SQLite is included by default with Sequelize. No additional installation needed.

**PostgreSQL takes too long to start**
- Render's free tier PostgreSQL can take 5-10 minutes to initialize
- Keep the FORCE_SQLITE fallback enabled during testing

### Docker Deployment

For Docker (e.g., with docker-compose):

```bash
# Development with PostgreSQL
docker-compose up

# Development with SQLite
FORCE_SQLITE=true docker-compose up
```

The `docker-compose.yml` includes PostgreSQL service configuration.
